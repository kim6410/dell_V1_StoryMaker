## 13. 다음 작업 권장 방향

인증 문제를 다시 해결할 때는 Beta 서비스가 V1 로그인 상태를 직접 조회하는 방식이 아니라, 다음 구조 중 하나로 설계해야 한다.

### 권장안 A: V1 백엔드 프록시

- 브라우저는 V1 동일 출처의 `/v1-api/beta/...`만 호출
- V1 백엔드에서 로그인 사용자 확인
- 인증된 요청만 내부 Beta 서비스 8021로 프록시
- V1 사용자 ID를 내부 헤더로 전달

### 권장안 B: 서명된 내부 토큰

- V1 백엔드가 로그인 사용자 ID를 포함한 짧은 유효기간의 내부 토큰 발급
- Beta가 같은 비밀키로 토큰 검증
- 브라우저는 직접 사용자 ID를 전달하지 않음

### 사용자별 보관함 분리 필수 사항

현재 `beta_jobs` 테이블에는 `owner_user_id` 컬럼이 있으나, 기존 레코드와 작업 생성·조회·삭제 흐름에서 사용자 소유권이 완전하게 연결되어 있는지 추가 검증이 필요하다.

다음 수정 전 반드시 확인할 항목:

1. 새 Beta 작업 생성 시 `owner_user_id` 저장 여부
2. 목록 조회 시 `WHERE owner_user_id = ?` 적용 여부
3. 상세·파일·삭제 시 해당 사용자 소유권 확인 여부
4. 관리자만 전체 목록을 볼 수 있는 별도 정책 여부
5. 기존 owner 없는 데이터의 마이그레이션 정책

단순 로그인 여부 확인만으로는 사용자별 보관함 분리가 되지 않는다.
