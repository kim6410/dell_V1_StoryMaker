## 1. 현재 목표

이번 작업의 핵심은 다음과 같습니다.

- 기존 회원과 WordPress 연결 상태 확인
- 업체 페르소나와 연락처 확인
- 회원별 요금제와 영상 제작 잔여 횟수 관리

- 결제일 기준 30일 갱신과 잔여량 이월 처리
- 기존 대시보드 구조와 제작 엔진에 영향 없이 관리자 화면만 확장

## 10. 정책상 확인이 필요한 불일치

최종 협의된 유료회원 이월률은 모두 30%입니다.

현재 DB는 Starter만 20%로 등록돼 있습니다.

```text
Starter 현재값: 20%
확정 정책: 30%
```

다음 작업에서 Starter 이월률을 30%로 수정해야 합니다.

## 11. 현재 확정 정책

- Free 가입 시 최초 1회만 20회 지급
- 동일 계정에 Free 최초 지급 중복 불가
- 이메일 인증 사용
- 업체명과 전화번호 중복 검사
- 유료회원만 30회 추가 충전 구매 가능
- 추가 충전 30회 가격 4,900원
- Free 결과물 저장기간 7일
- 유료회원 결과물 추가 저장기간 30일
- 갱신 기준은 매월 1일이 아니라 회원별 결제일 또는 가입일 기준 30일
- 유료회원 잔여량 이월률 30%
- 이월량은 소수점 올림
- 이월 계산 대상은 기본 월 제공량, 프로필 보상량, 커뮤니티 보상량
- 관리자 계정은 영상 제작 횟수 제한 없음

## 12. 다음 작업 우선순위

### 1순위: 기존 회원 과금 프로필 편입 방식 확정

추천 방식:

```text
1. 기존 일반회원 8명에게 Free 과금 프로필만 생성
2. 관리자 3명은 무제한 유지
3. Free 최초 20회는 회원별 확인 후 수동 지급
4. 과거 지급 이력이나 기존 사용량이 확인된 회원은 중복 지급 금지
```

과금 프로필만 일괄 생성하는 기능과 실제 횟수 지급은 반드시 분리합니다.

### 2순위: Starter 이월률 수정

Starter의 `rollover_percent`를 20에서 30으로 변경합니다.

변경 전 DB 백업과 변경 후 조회 검증이 필요합니다.

### 3순위: 관리자 수동 횟수 조정

회원 상세에서 다음 기능이 필요합니다.

- 횟수 추가
- 횟수 차감
- 사유 입력
- 관리자 확인창
- 원장 기록
- 관리자 작업 로그 기록

잔액을 직접 UPDATE하지 않고 반드시 지갑과 원장을 함께 기록해야 합니다.

### 4순위: 결제일 기준 자동 갱신

필요 기능:

- 회원별 `next_billing_at` 확인
- 결제일 기준 30일 갱신
- 기본 제공량 재지급
- 이전 기간 잔여량 30% 이월
- 소수점 올림
- 중복 갱신 방지용 idempotency key
- 실패 시 재시도 가능한 로그

### 5순위: 이월 엔진

이월 계산 대상:

```text

프로필 보상 잔여

```

이월 제외 후보:

```text

```

이월 제외 범위는 실제 구현 전에 최종 확인이 필요합니다.

### 6순위: 제작 횟수 예약·소비 연결

제작 시작 시 1회 예약하고 성공 시 소비, 실패 시 예약 해제하는 방식이 필요합니다.

```text
제작 요청
→ 사용 가능 횟수 확인
→ 1회 예약
→ 제작 성공 시 소비 확정
→ 제작 실패 시 예약 취소
```

기존 Queue, Worker, FFmpeg 흐름을 바꾸지 않고 제작 API 입구와 완료 처리 지점에만 연결해야 합니다.

### 7순위: 업체 한도 적용

- Free 1개

### 8순위: 추가 충전과 보상 관리

현재 가장 큰 미완료 지점은 기존 일반회원 8명이 아직 신규 과금 체계에 편입되지 않았다는 점입니다.

다음 작업은 기존 회원의 과금 프로필만 안전하게 생성한 뒤, 회원별 Free 최초 지급 여부를 확인하는 순서로 진행하는 것이 가장 안전합니다.

그다음 Starter 이월률 수정, 결제일 기준 갱신, 30% 이월, 제작 횟수 예약·소비 연결 순서로 진행합니다.

# 17. 앞으로 필요한 업무 전체 정리

현재 StoryMaker의 사용자 관리, 결제 관리, 등급 관리는 기본 구조와 관리자 조회 화면이 만들어진 상태입니다.

앞으로는 실제 운영에 필요한 회원 상태 관리, 과금 자동화, 사용량 차감, 갱신, 이월, 결제, 환불, 보상, 보관기간, 업체 한도, 관리자 감사 로그를 순차적으로 완성해야 합니다.

## 17.1 사용자 관리

회원 상태를 다음처럼 구분해 관리합니다.

```text
정상 회원
휴면 회원
이용 정지 회원
탈퇴 요청 회원
탈퇴 완료 회원
결제 연체 회원
환불 처리 회원
관리자 계정
테스트 계정
```

관리자 회원관리 화면에 필요한 기능:

```text
회원 활성·정지 전환
최근 로그인과 마지막 활동 확인
비밀번호 초기화 요청 처리
회원 탈퇴와 데이터 보관 처리
관리자 메모
회원별 작업 이력
회원별 영상 사용량
회원별 생성 콘텐츠 수
회원별 업체 목록
WordPress 연결 상태
이메일·전화번호·업체명 중복 확인
```

## 17.2 회원 권한과 요금제 분리

회원 역할과 구독 요금제는 별도로 관리합니다.

권장 역할:

```text
user
support
admin
super_admin
```

역할별 권한:

```text
user
- 본인 정보와 결제 정보만 관리

support
- 회원 조회와 문의 응대
- 결제·횟수 수정 불가

admin
- 회원 수정
- 요금제 변경
- 횟수 조정
- 보상 승인

super_admin
- 요금제 정책 변경
- 환불
- 관리자 권한 관리
- 일괄 작업
```

구독 요금제:

```text
Free
Starter
Standard
Professional
Business
```

## 17.3 기존 회원 과금 체계 편입

현재 일반회원에게 과금 프로필이 없습니다.

권장 편입 방식:

```text
관리자 계정
→ 무제한 유지
→ 과금 프로필 생성 제외

기존 일반회원
→ Free 과금 프로필 생성
→ 최초 20회는 회원별 확인 후 지급
```

과금 프로필 생성과 무료 횟수 지급은 분리합니다.

기존 회원 전체에게 자동으로 20회를 지급하지 않습니다.

```text
결제 요청 생성

다음 결제일 확인
결제 실패 알림
관리자 수동 결제 등록
```

결제 상태:

```text

```


결제 상태와 구독 상태는 별도 필드로 관리합니다.

## 17.5 요금제 변경 정책

업그레이드는 즉시 적용하는 방향이 단순하고 안전합니다.

```text
업그레이드 즉시 적용
새 요금제 기본 횟수 지급
변경일 기준 30일을 새 결제 기간으로 설정
```

다운그레이드는 현재 결제 기간 종료 후 적용하는 방향이 안전합니다.

Free 전환 시 결정할 항목:

```text
현재 유료 기간 종료일까지 기능 유지
업체 한도 초과 업체 처리
보관기간 30일에서 7일로 전환
추가 충전 잔여량 처리
이월 잔여량 처리
```

## 17.6 영상 제작 횟수 관리

제작 엔진과 과금 지갑을 다음 순서로 연결합니다.

```text
제작 시작
→ 사용 가능 횟수 확인
→ 1회 예약

제작 성공
→ 예약 1회를 실제 소비로 확정

제작 실패
→ 예약 1회를 원래 잔액으로 반환
```

상태 흐름:

```text
available
reserved
consumed
refunded
expired
```

동시 제작 시 잔액보다 많이 사용하는 것을 막기 위해 예약 단계가 반드시 필요합니다.

## 17.7 월간 갱신과 이월

회원별 결제일 기준 30일 갱신입니다.

갱신 작업 순서:

```text
이전 기간 잔여량 계산
이월 대상 계산
이월량 30% 계산
소수점 올림
새 기본 제공량 지급
새 만료일 설정
다음 결제일 30일 후로 변경
원장 기록
```

이월 대상:

```text
기본 월 제공량 중 남은 수량
프로필 보상량 중 남은 수량
커뮤니티 보상량 중 남은 수량
```

추가 충전량은 별도 지갑으로 유지하고 이월 대상에서는 제외하는 방향을 우선 적용합니다.

현재 DB에서 Starter 이월률이 20%로 등록돼 있으므로 30%로 수정해야 합니다.

# 18. 전체 UX 원칙

관리자와 사용자는 같은 정보를 같은 형태로 보면 안 됩니다.

관리자는 여러 회원을 비교하고 수정해야 합니다.

사용자는 본인의 현재 상태와 다음 행동만 쉽게 이해하면 됩니다.

```text
관리자 UI
- 많은 정보
- 검색과 필터
- 수동 조정
- 변경 이력
- 감사 로그
- 위험 작업 확인

사용자 UI
- 현재 상태 중심
- 쉬운 문구
- 남은 횟수 강조
- 결제와 충전 CTA
- 복잡한 원장 용어 숨김
```

## 18.1 공통 디자인 원칙

현재 V2의 짙은 남색·청록색 테마를 유지합니다.

상태 색상:

```text
정상·완료  청록 또는 초록
주의       노랑
오류·연체  빨강
정보       파랑
비활성     회색
관리자     보라 또는 청록
```

버튼 등급:

```text
기본 버튼  어두운 배경
주요 버튼  청록
위험 버튼  빨강
```

기술적인 내부 상태명을 사용자에게 그대로 노출하지 않습니다.


## 20.3 요금제 비교 화면

요금제별 카드에 다음 정보만 표시합니다.

```text
월 가격
월 영상 횟수
업체 수
이월률
보관기간
추천 대상
선택 버튼
```

현재 요금제에는 `현재 이용 중`, 추천 요금제 한 개에만 `가장 인기` 배지를 표시합니다.

## 20.4 업그레이드와 다운그레이드

업그레이드 전 결과 미리보기:

```text
Standard로 변경
월 9,900원
영상 제작 150회
업체 최대 5개
보관기간 30일
다음 결제일
```

다운그레이드는 다음 갱신일부터 적용합니다.

업체 한도를 초과할 경우 유지할 업체를 먼저 선택하게 합니다.

## 20.5 영상 횟수 화면

사용자는 내부 지갑 구조 대신 이해하기 쉬운 합계 화면을 봅니다.

```text
이번 달 기본 제공
이월
추가 충전
프로필 보상
커뮤니티 보상
총 사용 가능
```

만료 예정 횟수는 별도로 강조합니다.

## 20.6 추가 충전

유료회원에게만 다음 버튼을 노출합니다.

```text
영상 30회 추가하기
4,900원
```

구매 확인 화면:

```text
현재 잔여량
추가 충전 30회
구매 후 잔여량
결제 금액 4,900원
```

Free 회원에게는 요금제 전환 안내를 보여줍니다.

## 20.7 보상 화면

프로필 완성 보상은 진행률로 보여줍니다.

```text
업체 프로필 완성도 80%
업체명 완료
전화번호 완료
지역 완료
업종 완료
업체 소개 미완료
```

커뮤니티 보상 상태:

```text
검토 중
승인 완료
수정 필요
반려
```

반려 이유도 사용자에게 표시합니다.

## 20.8 모바일 UX

모바일 사용자 화면 순서:

```text
현재 요금제
남은 영상 횟수
빠른 제작 버튼
추가 충전
다음 결제일
업체 관리
결제 내역
```

관리자 모바일 화면은 조회와 간단 승인 중심으로 제한합니다.

복잡한 환불과 일괄 수정은 PC에서만 제공하는 방향이 안전합니다.
