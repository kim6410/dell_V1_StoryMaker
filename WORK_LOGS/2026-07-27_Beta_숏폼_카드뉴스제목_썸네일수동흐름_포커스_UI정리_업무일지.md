# StoryMaker Beta 숏폼·썸네일 흐름 정리 업무일지

작성일: 2026-07-27

작업 루트:

`/home/bourne/StoryMaker_1`

운영 화면:

`https://app.mystorymaker.net/v1/?page=betaProduction`

## 1. 작업 목적

StoryMaker Beta 숏폼 제작 화면에서 카드뉴스 콘텐츠를 영상 상단 문구와 썸네일 생성기에 일관되게 연결하고, MP4 제작 중 화면 포커스와 썸네일 선택 흐름을 사용자 중심으로 정리했다.

V1과 Beta 내부 중계 구조는 조사만 수행하고 기존 연결은 유지했다.

## 2. 내부 중계 읽기 전용 조사 결과

확인 항목:

- `STORYMAKER_BETA_INTERNAL_ORIGIN`
- `BETA_INTERNAL_AUTH_SECRET`
- Beta 서비스 포트 `8021`
- V1 프런트와 백엔드의 Beta 호출 경로
- V1 로그인 사용자 정보를 Beta로 전달하는 HMAC 서명 구조

확인된 호출 흐름:

```text
사용자 브라우저
→ /v1/beta/production
→ storymaker-v1-backend:8011
→ http://172.27.0.1:8021
→ storymaker-beta.service
```

확인 결과:

- V1 컨테이너 게이트웨이는 `172.27.0.1`이다.
- Beta는 `storymaker-beta.service`에서 `0.0.0.0:8021`로 실행된다.
- V1과 Beta 양쪽의 `BETA_INTERNAL_AUTH_SECRET`은 값 노출 없이 64자 설정 상태를 확인했다.
- `/v1/beta-api/*` 요청은 V1 로그인 사용자 정보를 HMAC-SHA256 서명 헤더로 Beta에 전달한다.
- Beta는 서명 유효시간 300초와 작업 소유자를 검증한다.
- 화면·API·정적 파일 중계는 정상 작동했다.
- 완전 독립 인증·도메인 분리는 작업 범위가 지나치게 커지므로 현재 연결 구조를 유지했다.

## 3. 숏폼 상단 제목을 카드뉴스 제목과 연결

수정 파일:

`StoryMaker_beta/app/beta_shortform.py`

기존 상태:

- 상단 1줄은 업체명 위주였다.
- 상단 2줄은 블로그 제목 또는 축약 제목을 사용했다.
- 제목 앞의 `##`, `1.`, `1)` 등이 화면과 MP4에 남을 수 있었다.

변경 내용:

- `CAROUSEL_7`의 Markdown 제목을 순서대로 추출한다.
- 카드뉴스 첫 번째 제목을 숏폼 상단 1줄로 사용한다.
- 카드뉴스 두 번째 제목을 숏폼 상단 2줄로 사용한다.
- `##`, `###`, 숫자 목록, 원문 앞 번호를 제거한다.
- 카드뉴스 제목이 부족한 기존 작업은 업체명·블로그 제목·작업 제목으로 폴백한다.
- 썸네일 iframe에 카드뉴스 원문을 직접 전달할 수 있도록 context에 `carousel_content`를 포함한다.

검증 예시:

```text
상단 1줄: 울산 북구 천곡동 누수 현장
상단 2줄: 철저한 사전 보양과 안전 점검
```

마크다운 `#` 포함 여부는 False로 확인했다.

## 4. 썸네일 생성기 카드뉴스 데이터 연결

수정 파일:

`storymaker-web/backend/app/static/v1/four-thumbnail/index.html`

자동 입력 기준:

```text
메인타이틀 → 카드뉴스 첫 번째 제목
서브 타이틀 → 카드뉴스 두 번째 제목
내용 → 카드뉴스 두 번째 제목 아래 본문
```

변경 내용:

- `CAROUSEL_7`을 `---` 구분선과 Markdown 제목 기준으로 블록화한다.
- 첫 번째 블록 제목을 메인타이틀에 연결한다.
- 두 번째 블록 제목을 서브 타이틀에 연결한다.
- 두 번째 블록 본문을 내용에 연결한다.
- `##`, 숫자 접두사, Markdown 기호를 제거한다.
- 카드뉴스가 없는 과거 작업은 기존 인스타그램·블로그 폴백을 유지한다.
- 부모 화면이 전달하는 `carouselContent`를 iframe에서 즉시 적용한다.
- iframe 내부의 별도 API 재조회가 실패해도 카드뉴스 문구가 남도록 보강했다.

최종 실검증:

```text
작업 ID: beta_20260727_193822_08f8fe
메인타이틀: 울산 시례동 공장 외벽 빗물 누수
서브 타이틀: 2층 배수관의 문제점 발견
내용: 현장을 살펴보니 2층 바닥에서 어정쩡하게 마감된 배수관이 원인이었습니다. 빗물이 그대로 1층 외벽을 적시고 있었죠.
```

## 6. 숏폼 제작 화면 불필요 카드 제거

수정 파일:

`StoryMaker_beta/static/production.html`

화면에서 제거한 영역:

- 미디어 설정(이미지·동영상) 카드
- MP4 제작 진행 로그 카드

제작 코드가 참조하는 DOM 요소는 삭제하지 않고 숨김 상태로 유지했다.

유지 요소:

- `sf-images`
- `sf-videos`
- `sf-image-connected`
- `sf-video-connected`
- `sf-log`

따라서 기존 이미지 자동 연결, MP4 렌더링, 자동 저장 기능은 유지된다.

## 7. 영상 제작 중 미리보기 포커스 유지

수정 파일:

`StoryMaker_beta/static/beta-shortform-inline.js`

변경 내용:

- 영상 만들기 클릭 즉시 오른쪽 영상 미리보기 카드로 부드럽게 이동한다.
- TTS·SRT·MP3 준비 중에도 같은 위치를 유지한다.
- MP4 프레임 생성 중에도 포커스를 유지한다.
- MP4 완료 후에도 미리보기 위치를 유지한다.
- V1 본문 iframe 안에서 실행되는 경우 상위 프레임의 스크롤 위치까지 계산한다.
- 썸네일 제작 버튼을 누를 때만 포커스 잠금을 해제한다.

## 8. 하단 버튼 구조 변경

기존:

```text
Play | Stop | 보관함 바로가기
```

변경:

```text
Play/Stop 토글 | 썸네일 제작 | 보관함 바로가기
```

동작:

- 왼쪽 버튼은 재생 중 `Stop`, 정지 중 `Play`로 전환된다.
- 가운데 버튼은 썸네일 제작 영역을 수동으로 펼치고 해당 위치로 이동한다.
- MP4 완료 후 썸네일 영역은 자동으로 펼쳐지지 않는다.

## 9. 보관함 이동 전 썸네일 확인 흐름

대표 썸네일이 저장되지 않은 상태에서 보관함 바로가기를 누르면 다음 확인창을 표시한다.

```text
썸네일 제작 하시겠습니까?
YES / NO
```

동작:

- YES: 팝업을 닫고 썸네일 제작 영역을 펼친 뒤 해당 위치로 이동한다.
- NO: 팝업을 닫고 보관함으로 이동한다.
- 팝업 바깥 클릭 또는 ESC: 팝업을 닫는다.
- 대표 썸네일이 서버에 저장돼 있으면 팝업 없이 보관함으로 이동한다.

저장 여부는 다음 두 조건으로 확인한다.

- `selected_template_id` 존재
- 선택 템플릿 PNG 파일 존재

초기 진입 때 팝업이 강제로 표시된 원인도 수정했다.

원인:

- `hidden` 속성과 인라인 `display:flex`가 충돌했다.

조치:

- 초기 `display:flex`를 제거했다.
- 팝업을 열 때만 JavaScript로 `display:flex`를 적용한다.
- 닫을 때 `display:none`과 `hidden=true`를 함께 적용한다.

## 14. 다음 작업 기준

- MP4 완료 후 썸네일 영역 자동 펼침을 다시 추가하지 않는다.
- 카드뉴스 첫 번째 제목은 썸네일 메인타이틀과 숏폼 상단 1줄에 사용한다.
- 카드뉴스 두 번째 제목은 썸네일 서브 타이틀과 숏폼 상단 2줄에 사용한다.
- 카드뉴스 두 번째 본문은 썸네일 내용에 사용한다.
- 보관함 이동 전 썸네일 미저장 확인 절차를 유지한다.
- 미디어 설정 카드와 진행 로그 카드는 화면에 다시 노출하지 않는다.
- V1·Beta 내부 중계는 현재 구조를 유지한다.
