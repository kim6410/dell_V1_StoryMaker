## 5. 실제 브라우저 검증 결과

### 5-1. 로그인 모달 최초 진입

확인 URL 직접 접속 시 로그인 모달이 정상 표시됐다.

`#storymaker-login-modal` DOM 개수는 1개였다.

화면에 표시된 모달 개수도 1개였다.

통합 모달 소유권 표시는 다음과 같았다.

`data-unified-auth="1"`

오래된 레거시 로그인 모달은 나타나지 않았다.

### 5-2. 회원가입 탭

로그인 모달 내부에서 회원가입 탭을 직접 클릭했다.

별도 모달을 새로 만들지 않고 동일한 통합 모달 내부에서 화면만 전환됐다.

표시 항목:

- 사용자명
- 이메일
- 인증 메일 받기
- 메일에서 비밀번호를 설정하면 가입이 완료된다는 안내

회원가입 탭 진입 후에도 DOM 모달 개수는 1개였다.

### 5-3. 비밀번호 찾기

로그인 화면에서 비밀번호 찾기를 직접 열었다.

동일 통합 모달 안에서 다음 화면이 표시됐다.

- 비밀번호 재설정
- 가입 시 사용한 이메일 안내
- 이메일 주소 입력창
- 재설정 링크 보내기
- 로그인으로 돌아가기

별도의 오래된 비밀번호 찾기 모달은 나타나지 않았다.

### 5-4. 닫기와 재열기

모달 닫기 후 회원가입 화면을 다시 열었다.

다시 비밀번호 찾기를 열었다.

닫기와 재열기를 반복해도 모달 DOM 개수는 계속 1개였다.

### 5-5. 반복 호출 회귀 테스트

로그인·회원가입·비밀번호 찾기 화면을 총 12회 연속 호출했다.

검증 결과:

- 모달 DOM 개수 1개 유지
- 화면 표시 모달 1개 유지
- 통합 모달 소유권 유지
- 중복 오버레이 없음
- 레거시 모달 재등장 없음

### 5-6. 잘못된 로그인 실제 제출

테스트 사용자명:

`__modal_probe_invalid__`

잘못된 비밀번호로 실제 로그인 요청을 전송했다.

표시된 오류:

`아이디 또는 비밀번호가 일치하지 않습니다.`

오류 메시지는 통합 모달 내부에 정상 표시됐다.

오류 발생 뒤에도 모달은 1개만 유지됐다.

### 5-7. 회원가입 입력 검증

회원가입 화면에서 입력값이 부족한 상태로 실제 제출을 실행했다.

표시된 검증 메시지:

`사용자명을 입력해 주세요. 한글 이름도 사용할 수 있습니다.`

회원가입 입력 검증 과정에서도 다른 모달이 나타나지 않았다.

## 10. app_auth.js 레거시 모달 코드 상태

`app_auth.js`의 `ensureStoryMakerLoginModal()` 내부에는 과거 레거시 모달 HTML 생성 코드가 아직 남아 있다.

현재는 함수 시작 부분에서 다음 통합 모달로 위임한다.

`window.StoryMakerV1AuthModal.ensure()`

통합 모달이 없으면 오류를 발생시키므로 아래쪽 레거시 HTML 생성 블록은 현재 실행되지 않는다.

현재 브라우저에서는 안전하지만 장기적으로는 회귀 위험과 코드 혼란이 남는다.

레거시 모달 HTML은 바로 제거하지 않는다.

실제 신규 가입·로그인·로그아웃·비밀번호 재설정 전체 흐름을 먼저 통과한 뒤 사용처를 다시 검색하고 제거한다.

제거할 때 유지해야 하는 기능:

- 통합 모달 위임 함수
- 로그인 API 처리
- 로그인 상태 확인
- 쿠키 인증 복구
- 로그아웃
- 마이페이지
- 사용자 작업공간 복구

제거 후보는 사용되지 않는 레거시 DOM 생성 블록만 해당한다.
