작성일: 2026-07-27

- `/home/bourne/StoryMaker_1/storymaker-web/backend/app/api/auth.py`

- `/home/bourne/StoryMaker_1/storymaker-web/backend/app/static/v1/index.html`

## 작업 목적
사용자가 V1 가입·로그인 통합 모달 안에서 이메일을 입력하면 외부 WordPress 화면으로 이동하지 않고 실제 WordPress 비밀번호 재설정 메일 발송 요청이 수행되도록 연결한다.

## 수정 내용
### V1 백엔드 API 추가
- `POST /v1-api/auth/password-reset-request`
- 요청 JSON: `{"login":"사용자 이메일"}`
- WordPress 코어 `/wp-login.php?action=lostpassword`에 `user_login` 전달
- WordPress 메일 서버 오류 감지 시 HTTP 502 반환
- 계정 존재 여부는 사용자에게 노출하지 않음
- 정상 요청은 항상 동일한 안내 반환

정상 안내:
`입력한 정보와 일치하는 계정이 있으면 비밀번호 재설정 메일을 발송했습니다. 메일함과 스팸함을 확인해 주세요.`

### V1 모달 연결
기존에는 WordPress 비밀번호 찾기 외부 페이지로 이동했다.

변경 후:
- 모달 내부에서 이메일 형식 확인
- 버튼 문구를 `메일 발송 요청 중...`으로 전환
- `/v1-api/auth/password-reset-request` 호출
- 성공 시 통합 완료 패널 표시
- 실패 시 같은 모달 안에 오류 표시

### API
빈 입력:
- HTTP 400
- `이메일 또는 사용자명을 입력해 주세요.`

존재하지 않는 이메일:
- HTTP 200
- 계정 존재 여부를 노출하지 않는 동일 안내 반환

WordPress 공개 비밀번호 찾기 경로:
- GET HTTP 200
- `lostpasswordform`, `user_login`, 제출 버튼 존재 확인
- 존재하지 않는 이메일에 WordPress가 계정 없음 오류를 반환하는 것 확인
- V1 API에서는 이 정보를 외부에 노출하지 않도록 처리

## 실제 메일 수신 검증 범위
