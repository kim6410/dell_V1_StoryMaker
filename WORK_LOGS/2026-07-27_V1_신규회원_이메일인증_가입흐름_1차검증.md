# StoryMaker V1 신규회원 이메일 인증 가입 흐름 1차 검증

작성일: 2026-07-27

## 작업 목표

사용자가 보는 V1 회원가입 모달을 간소화하고 신규 가입자에게만 이메일 확인 절차를 적용한다.

기존 회원 로그인과 기존 WordPress 계정은 변경하지 않는다.

## 기존 구조 확인

Hostinger WordPress 플러그인:

`wp-content/plugins/storymaker-auth/storymaker-auth.php`

기존 버전: 1.0.1

기존 동작:

- 회원가입 REST: `/wp-json/storymaker/v1/register`
- `register_new_user()` 호출 시 WordPress 계정을 즉시 생성
- WordPress 코어가 비밀번호 설정 메일 발송
- `email_verified`가 실제 상태와 관계없이 항상 `true`
- V1 회원가입 모달은 비밀번호를 받지만 WordPress 플러그인은 해당 비밀번호를 사용하지 않음

## 적용 내용

### Hostinger WordPress 플러그인

버전 1.0.1 → 1.1.0

자동 백업:

`domains/mystorymaker.net/public_html/_mcp_backups/20260726_200811_015755/wp-content__plugins__storymaker-auth__storymaker-auth.php`

신규 가입자에게만 다음 사용자 메타를 적용:

`storymaker_email_verified=0`

WordPress 비밀번호 설정 메일의 링크를 통해 비밀번호 설정이 완료되면 `after_password_reset` 훅에서:

`storymaker_email_verified=1`

기존 회원은 해당 메타가 없으므로 인증 완료로 간주하여 기존 로그인 동작 유지.

신규 가입자가 메일 비밀번호 설정을 완료하지 않은 상태에서 인증에 성공할 경우 `email_verification_required` HTTP 403 반환.

### V1 회원가입 모달

수정 파일:

`/home/bourne/StoryMaker_1/storymaker-web/backend/app/static/v1/auth/auth_modal_unified.js`

변경 내용:

- 회원가입 비밀번호 입력 제거
- 입력 단계: 사용자명 + 이메일 2개
- CTA: `인증 메일 받기`
- 안내: `메일에서 비밀번호를 설정하면 가입이 완료됩니다.`
- WordPress 회원가입 REST에는 username/email만 전송
- 성공 제목: `인증 메일을 보냈습니다`

캐시 버전:

`20260727-v1-auth-ux-4`

## 검증 중 생성된 테스트 대기 계정

기존 사용자명이라고 가정한 `StoryMaker` 값이 실제 WordPress user_login이 아니어서 테스트 요청이 신규 계정을 생성함.

- WordPress user_id: 19
- email: `storymaker-probe-20260727@example.com`
- 상태: 신규 이메일 인증 대기 메타가 적용되는 대상
- 추가 중복 요청은 HTTP 400으로 차단 확인

이 계정은 테스트용이며 실제 사용자 계정이 아니다. SSH에서 WP-CLI로 신원 재확인 후 삭제한다.

확인 명령:

`wp user get 19 --fields=ID,user_login,user_email,roles,registered`

삭제 명령:

`wp user delete 19 --yes`

삭제 전 출력에서 이메일이 정확히 `storymaker-probe-20260727@example.com`인지 반드시 재확인한다.

## 현재 판단

신규 가입 UX는 사용자명과 이메일만 입력하고, WordPress 코어 메일에서 비밀번호를 설정하는 2단계 구조로 단순화됐다.

기존 회원은 인증 메타가 없으므로 영향받지 않는다.

실제 일반 사용자 이메일로 가입 신청 → 메일 수신 → 비밀번호 설정 → 로그인까지 최종 E2E가 남아 있다.
