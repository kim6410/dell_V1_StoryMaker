## 1. 쿠키 로그아웃 실제 DB 검증

내장 `guest` 계정으로 `/v1-api/auth/login`을 호출해 쿠키 기반 세션을 생성했다.

검증 세션:

- session_id: 59
- user_id: 81

로그아웃 전:

- login_at: `2026-07-26 19:04:33`
- last_seen_at: `2026-07-26 19:04:33`
- logout_at: `NULL`
- duration_seconds: 0

Authorization 헤더 없이 쿠키만 전송해 다음 API를 호출했다.

`POST /v1-api/auth/logout`

응답:

`{"ok":true,"data":null,"message":"안전하게 로그아웃되었습니다."}`

로그아웃 후 동일 세션 행:

- logout_at: `2026-07-26 19:04:33`
- last_seen_at: `2026-07-26 19:04:33`
- duration_seconds: 0

판정:

쿠키 JWT의 `session_id`를 사용해 `user_sessions.logout_at`이 실제 기록되는 것을 확인했다.
이번 보강은 정상 동작한다.

## 2. WordPress 사용자 조회 401 조사

대상 코드:

`storymaker-web/backend/app/api/admin_members.py`

호출 방식:

- URL: `https://mystorymaker.net/wp-json/wp/v2/users`
- 인증: HTTP Basic + WordPress Application Password
- context: edit

환경변수 상태:

- WORDPRESS_API_URL: 설정됨
- WORDPRESS_USERNAME: `StoryMaker`
- WORDPRESS_APP_PASSWORD: 설정됨
- 비밀값은 출력하지 않음

실제 응답:

- `/users?context=edit`: HTTP 401
- 코드: `rest_forbidden_context`
- 메시지: 사용자를 편집할 권한이 없음

추가 인증 확인:

- `StoryMaker` + 현재 Application Password → `/users/me` HTTP 401 `rest_not_logged_in`
- `ha` + 현재 Application Password → `/users/me` HTTP 401 `rest_not_logged_in`

판정:

현재 컨테이너의 Application Password는 WordPress에서 유효한 인증 수단으로 인정되지 않는다.
사용자명 권한 문제 이전에 Application Password가 폐기됐거나 다른 계정에 발급됐거나 값이 불일치한 상태다.

또한 인증되지 않은 WordPress 사용자 목록 요청 일부는 Hostinger 보안 계층에서 HTTP 403 HTML 응답으로 차단된다.

## 3. 현재 안전 판단

- 쿠키 로그아웃 세션 종료 기록: PASS

유효한 관리자 Application Password가 새로 발급되어 V1 컨테이너 환경변수에 반영되기 전까지 회원관리의 WordPress 실시간 연결은 복구할 수 없다.

기존 비밀값을 추측하거나 WordPress DB를 직접 변경하지 않는다.
