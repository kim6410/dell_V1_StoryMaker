## 기존 문제

`DELETE /beta-api/jobs/{beta_job_id}`가 작업 폴더를 삭제한 뒤 아래 SQL을 실행했다.

```sql
DELETE FROM beta_jobs WHERE beta_job_id=?
```

그 결과 사용량·과금·추이 분석에 필요한 Beta 작업 DB 기록과 보관함 목록이 모두 사라졌다.

## 변경 내용

### DB 컬럼 추가

`beta_jobs`에 다음 컬럼을 추가했다.

- `media_deleted_at TEXT NOT NULL DEFAULT ''`
- `media_deleted_bytes INTEGER NOT NULL DEFAULT 0`
- `media_delete_reason TEXT NOT NULL DEFAULT ''`

기존 34개 운영 작업은 모두 그대로 유지되며 신규 컬럼 기본값은 빈 값 또는 0이다.

### 삭제 API 변경

사용자 또는 관리자가 삭제를 누르면 다음만 수행한다.

1. 작업 소유자 확인
2. 작업 폴더 전체 용량 계산
3. 작업 폴더를 격리 경로로 이동
4. 실제 작업 파일 삭제
5. `beta_jobs` 행은 유지
6. 삭제 시각·용량·사유만 UPDATE
7. 공유 이미지 중 다른 작업에서 참조하지 않는 파일만 정리

응답 기준:

- `db_deleted: false`
- `db_preserved: true`
- `list_preserved: true`
- `files_deleted: true/false`

### 목록과 상세 조회

관리자와 일반 사용자 목록 모두 삭제된 작업을 계속 반환한다.

작업 폴더가 없어도 상세 API는 DB의 제목·상태·생성시각·완료시각·삭제 메타데이터를 반환한다. 미디어 자산은 빈 상태로 표시한다.

### 화면 변경

삭제 버튼을 관리자 전용이 아니라 작업 소유 사용자에게도 표시한다.

문구:

- 삭제 전: `파일 삭제`
- 삭제 후: `파일 삭제됨`
- 확인: `목록과 DB는 남기고 저장 파일만 삭제할까요?`

삭제 성공 후 프런트 배열에서 항목을 제거하지 않고 목록을 다시 불러온다.
