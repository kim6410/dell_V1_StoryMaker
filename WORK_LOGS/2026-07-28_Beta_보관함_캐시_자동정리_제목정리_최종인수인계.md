### 3.1 Beta 보관함 진입 속도 개선

기존 문제:

- `/beta-api/jobs` 목록 조회 후 모든 작업의 상세 API를 `Promise.all()`로 다시 호출했다.

- 목록 진입은 `/beta-api/jobs` 요약 캐시만 사용.
- 상세정보는 사용자가 게시물을 클릭할 때 해당 작업 1건만 조회.
- 관리자 캐시와 사용자별 캐시를 서비스 시작 시 미리 생성.

### 3.3 자동 정리 안정성 보강

발견했던 위험:

- V1 회원 DB를 순간적으로 읽지 못하면 무료로 오판해 10건까지 삭제할 가능성.
- 삭제 도중 서버가 중단되어 격리 폴더가 남으면 다음 실행에서 원본을 잘못 제거할 가능성.
- 미디어가 없는 미완성 작업이 한도 계산에 포함될 가능성.
- 프로세스 내부 잠금만 있어 향후 다중 워커에서 중복 삭제 가능성.
- 서비스 시작 1회 점검만으로 외부 경로에서 생긴 누락 데이터를 다음 재시작까지 놓칠 가능성.
- 감사 로그 무한 증가 가능성.

완료 조치:

- 회원 등급 확인 실패 시 삭제를 실행하지 않는 안전 우선 방식으로 변경.

- 미디어가 실제 존재하는 작업만 보관 한도에 포함.
- 격리 폴더 장애 복구 로직 추가.
  - DB 반영 전 중단: 원본 복구.
  - 축약 메타데이터 작성 후 DB 반영 전 중단: 축약본 제거 후 원본 복구.

  - DB에는 삭제 표시가 있지만 축약 메타데이터가 없음: 원본 복구 후 DB 삭제 표시 롤백.
  - 상태 판단 불가: 삭제하지 않고 감사 로그 기록.
- 보관함 진입 재검증과 1시간 주기 스케줄러 추가.
- 실제 삭제가 발생한 경우에만 공유 이미지 전체 참조 검사 실행.

- 시작 점검 오류가 있어도 Beta 서비스 자체는 기동하고 다음 주기에 재시도.
