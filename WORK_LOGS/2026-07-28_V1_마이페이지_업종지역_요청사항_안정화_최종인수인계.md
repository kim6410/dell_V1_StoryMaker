### 3.4 업종 표시창 비동기 동기화 보강

문제:

React가 서버에서 저장된 페르소나를 비동기로 불러온 뒤 원본 업종 `<select>`를 변경해도, 업종 검색 스크립트가 만든 표시용 입력창은 초기 기본값을 유지했다.

조치:

원본 업종 `<select>`의 현재 선택값과 표시용 입력창을 주기적으로 동기화하는 `syncDisplay()`를 추가했다.

### 3.5 지역 표시·재진입 로딩 문제 조사 및 여러 차례 보강

적용한 보강:

1. 원본 지역 필드 변경을 표시용 입력창에 주기적으로 반영하는 `syncDisplay()` 추가
2. 원본 지역 필드가 빈 경우 `/v1-api/auth/personas`에서 기본 페르소나 지역을 다시 읽는 `hydrateRegionFromSavedPersona()` 추가
3. 표시용 지역 입력창이 실제 지역 필드로 다시 바인딩되지 않도록 제외
4. `지역 필수` 라벨에서 실제 `<select>`를 우선 선택
5. 실제 React 지역 `<select>`를 새 래퍼 안으로 이동하지 않고 원래 DOM 위치에 유지
6. 표시용 입력창 참조는 `field.__v1RegionDisplay`로 관리

## 5. 확인된 마이페이지 구조

React 번들 안에는 마이페이지 성격의 컴포넌트가 두 종류 있다.

### 데스크톱 V1 마이페이지

컴포넌트 식별:

`Wj({open:e, authState:r, onClose:n, onSelectBusiness:i})`

현재 사용자 스크린샷에 보이는 화면이다.

특징:

`마이페이지`

`업체 페르소나 관리`

`계정 및 연동 설정`

업종과 지역을 직접 편집한다.

### 모바일 작업실용 업체·페르소나 관리 화면

컴포넌트 식별:

`l5({open:e, authState:r, personas:n, ...})`

화면 크기·작업실 흐름에 따라 사용되는 별도 관리 컴포넌트다.

현재 두 컴포넌트가 동시에 겹쳐 뜨는 것으로 확인되지는 않았다.

그러나 동일한 업체·페르소나 데이터와 유사한 편집 기능을 각각 구현하고 있어 유지보수 혼선이 크다.

사용자 의도:

실제로 사용하지 않는 마이페이지는 일단 나오지 않게 한다.

권장 방향:

`l5`는 모바일 작업실에서 실제 사용 여부를 확인한 뒤, 미사용이면 진입 경로만 숨긴다.

컴포넌트 코드를 즉시 삭제하지 않는다.

### 3단계: 지역 검색을 React 원본 컴포넌트에 통합

현재처럼 외부 스크립트가 React `<select>`를 숨기고 표시용 입력창을 덧씌우는 방식은 비동기 상태와 충돌 가능성이 크다.

가장 안전한 해결 방향:

`Wj`의 지역 필드 렌더링 자체를 아래 구조로 직접 수정한다.

저장된 `g.region`을 읽기 전용 표시 입력창에 직접 렌더링

지역 검색 버튼을 React 상태 갱신 함수 `K("region", value)`와 연결

팝업 선택 시 React 상태를 직접 변경

외부 스크립트는 팝업 UI만 제공하거나 제거

이렇게 하면 Ctrl+R 후 `nc()`가 페르소나를 불러와 `y(cb(Q))`를 실행할 때 지역이 React 상태로 정상 표시된다.
