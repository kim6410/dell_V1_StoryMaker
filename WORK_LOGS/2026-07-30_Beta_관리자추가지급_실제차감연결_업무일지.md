# Beta 관리자 추가 지급 실제 차감 연결 업무일지

작성일: 2026-07-30

## 문제

무료회원에게 관리자가 20회를 추가 지급해도 Beta 딸깍 제작은 별도 `beta_mp4_usage`의 고정 월 20회 규칙만 확인해 제작을 차단했습니다.

관리자 지급 데이터는 V1 DB의 `video_credit_wallets`에 정상 저장돼 있었지만 Beta 사용량 로직이 이 지갑을 읽거나 차감하지 않았습니다.

## 정책

- 무료회원 기본 제공: 가입 기준 30일마다 20회
- 관리자 추가 지급: V1 영상 크레딧 지갑 잔액만큼 추가 사용
- 유료회원: 무제한
- 관리자: 무제한

## 수정 파일

- `StoryMaker_beta/app/beta_mp4_usage.py`
- `StoryMaker_beta/app/beta_jobs.py`

## 구현

### 사용 가능 여부

무료회원의 현재 기간 기본 잔여량과 V1 DB의 추가 지급 지갑 잔액을 함께 계산합니다.

- `monthly_remaining`: 기본 20회 중 남은 수량
- `bonus_remaining`: `credit_type!='free_monthly'` 지갑의 사용 가능한 잔액
- `remaining`: 두 잔액의 합
- 둘 중 하나라도 남으면 `access_allowed=true`

### 추가 지급분 예약

현재 기간의 완료 및 예약 작업이 기본 20회 이상이면 다음 순서로 처리합니다.

1. 만료되지 않은 추가 지급 지갑 검색
2. `reserved_amount` 1 증가
3. `beta_mp4_usage.credit_wallet_id`에 지갑 ID 기록
4. MP4 완성 전에는 실제 `available_amount`를 차감하지 않음

### 정상 완료 차감

MP4 검증이 성공하면 해당 지갑에서 다음을 원자적으로 처리합니다.

- `available_amount` 1 차감
- `reserved_amount` 1 반환
- `video_credit_ledger`에 사용 기록 추가

같은 작업 결과가 다시 저장되어도 기존 완료 상태를 확인해 중복 차감하지 않습니다.

### 실패·장기 정지 반환

2시간 이상 남은 미완료 예약은 정리할 때 연결된 지갑의 `reserved_amount`를 반환합니다.

## DB 보강

`beta_mp4_usage`에 다음 컬럼을 안전하게 추가했습니다.

- `credit_wallet_id INTEGER`

기존 레코드는 그대로 유지됩니다.
