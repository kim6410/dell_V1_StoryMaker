## 2. 현재 최종 정상 상태

현재 모바일 화면은 정상 작동 상태로 확인되었다.

유지되어야 할 모바일 화면 기준은 다음과 같다.

- 모바일 딸깍 제작 화면 정상 표시
- 모바일 전용 화면 구성 유지
- Browser AI 자동 로딩 차단
- 모바일에서는 글과 사진 생성 및 저장까지만 수행
- 팟캐스트, 숏폼 MP4, 썸네일 제작은 PC에서 이어서 진행
- 모바일 하단 기존 메뉴 정리
- 관리자 회원 관리 버튼의 모바일 상단 배치 유지
- PC 화면과 PC 제작 기능에는 영향 없음

현재 운영 `/v1/`과 관련 정적 파일은 HTTP 200으로 확인되었다.

## 4. 이번 모바일 화면 문제의 경위

모바일→PC Beta 보관함 연동 작업 후 모바일 화면이 이전 화면처럼 보이는 문제가 발생했다.

조사 과정에서 모바일 전용 화면을 구성하던 `mobile-beta-footer.js`와 `mobile-beta-footer.css`를 이전 화면 원인으로 오판해 제거하면서 실제 최신 모바일 화면 구성이 사라졌다.

이후 잘못 추가한 임시 cleanup 파일도 있었으나 최종적으로 제거했다.

현재는 정상 모바일 화면 파일을 복원한 상태다.

잘못 추가했다가 제거한 파일:

- `mobile-pc-continue-cleanup.js`
- `mobile-pc-continue-cleanup.css`

이 두 파일은 다시 추가하지 않는다.

## 5. 모바일→PC Beta 보관함 연동

모바일 원샷 작업이 Gemini 글과 사진 생성을 완료하면 PC Beta 보관함에 동일 작업이 생성되도록 연동했다.

핵심 파일:

- `/home/bourne/StoryMaker_1/storymaker-web/backend/app/api/mobile_one_shot.py`
- `/home/bourne/StoryMaker_1/storymaker-web/backend/app/api/content_board.py`
- `/home/bourne/StoryMaker_1/storymaker-web/docker-compose.yml`

핵심 함수:

- `_sync_mobile_result_to_beta_archive(...)`

모바일 작업 ID 형식:

- `mob-YYYYMMDDHHMMSS-xxxxxxxx`

Beta 보관함 작업 ID 형식:

- `beta_YYYYMMDD_HHMMSS_xxxxxxxx`

모바일 완료 작업은 다음 상태를 사용한다.

- `status = gemini_completed`
- `progress = 100`
- `pipeline.defer_media_to_pc = true`
- `media.status = pc_continue_waiting`
- MP3 없음
- MP4 없음
- 썸네일 없음

Beta 보관함에는 글 채널과 이미지가 저장되고, PC에서 후속 제작을 진행한다.

## 10. 절대 주의사항

- 모바일 화면이 정상일 때 임의로 정적 파일을 삭제하지 않는다.
- `mobile-beta-footer.js/css`를 이전 화면 원인으로 판단하지 않는다.
- 별도 cleanup JS/CSS를 추가하지 않는다.
- React 본체 번들을 추측으로 교체하지 않는다.
- 모바일 화면 수정 전 반드시 백업을 만든다.
- PC 영향 여부를 반드시 분리 검증한다.
- 모바일 전용 코드는 `max-width: 767px` 조건을 유지한다.
- 기존 미완료 Git 변경을 한꺼번에 커밋하지 않는다.
- `git add .` 또는 광범위 스테이징을 사용하지 않는다.
- `.env` 또는 API 키를 출력하거나 커밋하지 않는다.
- 백엔드 재생성 또는 재시작 전 DB pool 상태와 정적 파일 마운트를 확인한다.

## 11. 화면이 다시 하얗게 보일 때

먼저 수정하지 말고 아래만 확인한다.

1. `/v1/` HTTP 상태
2. React 본체 JS HTTP 상태
3. CSS HTTP 상태
4. 모바일 정적 JS/CSS HTTP 상태
5. `storymaker-v1-backend` 최근 로그
6. 로그인 API의 401과 실제 500 오류를 구분

하얀 화면이 잠시 나타났다가 복구된 사례가 있었으며, 당시 정적 파일은 모두 HTTP 200이었다.

따라서 즉시 파일을 롤백하거나 삭제하지 말고 실제 브라우저 로딩 상태를 먼저 확인한다.
