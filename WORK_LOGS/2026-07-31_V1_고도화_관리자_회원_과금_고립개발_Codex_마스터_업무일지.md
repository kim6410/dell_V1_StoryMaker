## 2. StoryMaker 관리자 플랫폼의 최종 지향점

StoryMaker 관리자 화면은 단순한 회원 목록이나 설정 화면이 아니다.

최종적으로는 다음을 한 화면 체계에서 관리하는 소상공인 콘텐츠 SaaS 운영 콘솔이 되어야 한다.

- 회원과 사업체
- 무료·유료 구독
- 월간 제작 한도
- AI 원고 제작 사용량
- 이미지·MP3·MP4·썸네일 저장량
- 업종과 업종별 프롬프트
- 지역·법정동·콘텐츠용 지역명
- 제작 작업 큐와 실패 작업
- 사용자 요청사항
- 운영 공지와 알림
- 결제·환불·쿠폰·프로모션
- 보관함 데이터와 미디어 연결
- AI Provider 사용량과 비용
- 시스템 상태와 장애 이력
- 관리자 감사 로그
- 매출·전환·재방문·이탈 분석

운영자가 회원 한 명을 클릭했을 때 다음 질문에 즉시 답할 수 있어야 한다.

- 누구인가?
- 어떤 업체를 운영하는가?
- 어떤 업종과 지역을 선택했는가?
- 언제 가입했는가?
- 무료인가, 유료인가?
- 구독 시작일과 종료일은 언제인가?
- 이번 달 몇 개의 콘텐츠를 제작했는가?
- MP4와 썸네일은 몇 개 저장했는가?
- 실패한 작업이 있는가?
- 저장 용량은 얼마나 쓰는가?
- 최근 접속일은 언제인가?
- 어떤 기능을 자주 사용하는가?
- 결제 실패나 환불 이력이 있는가?
- 관리자 지원이 필요한가?

## 3. 현재 구현되어 있는 관리자 핵심 기능

### 3.1 관리자 전용 메뉴

현재 V1은 일반 사용자와 관리자 메뉴를 구분한다.

관리자에게는 다음 운영 메뉴가 노출되는 구조를 유지한다.

- 회원관리
- 작업 큐
- 업종별 관리
- 관리자 요청사항
- AI 연구실
- 네모트론 연구실
- 운영·사용현황 관련 카드

일반 사용자에게 관리자 전용 메뉴가 노출되지 않아야 한다.

### 3.2 회원관리

현재 회원관리 화면은 단순 이메일 목록이 아니라 다음 정보를 확장하는 방향으로 고도화되어 있다.

- 회원 ID
- 이메일
- 표시 이름
- 역할
- 가입일
- 최근 로그인
- 활성·비활성 상태
- 무료·유료 상태
- 구독 시작일
- 구독 종료일
- 월간 제작 한도
- 월간 사용량
- 전체 프로젝트 수
- Beta 프로젝트 수
- 저장 용량
- 기본 업체 정보
- 업종
- 지역
- 사용자 요청사항

회원 상세 화면은 상단 요약 카드와 하단 상세 섹션으로 구성하는 것이 적합하다.

### 3.3 마이페이지

마이페이지는 사용자의 업체 페르소나와 구독 정보를 관리하는 핵심 화면이다.

주요 기능:

- 업체명
- 대표 전화번호
- 업종 선택
- 콘텐츠용 지역명
- 행정 지역명
- 업체 소개
- 주요 서비스
- 키워드
- 기본 페르소나 지정
- 구독 상태 확인
- 사용량 확인
- 요청사항 등록
- Beta 보관함 안내

업종 검색 모달은 정적 목록이 아니라 DB의 활성 업종을 직접 조회한다.

현재 활성 업종 전체가 카테고리별로 표시되고, 검색 결과가 없으면 카카오톡 채널로 업종 추가 요청을 보낼 수 있다.

카카오톡 채널:

`https://pf.kakao.com/_FxjaxnX`

### 3.4 업종별 관리

업종별 관리 화면은 StoryMaker 품질을 좌우하는 핵심 관리자 기능이다.

현재 구조:

- 카테고리별 업종 그룹
- 업종명
- 업종 키
- 활성·비활성 상태
- 순서 변경
- 이름 수정
- 업종 추가
- 업종별 프롬프트 버튼
- 행 아래 인라인 프롬프트 편집기
- 검색
- 페이지당 12개 표시

업종별 세부 지침은 다음 다섯 종류를 유지한다.

- `prompt_guidance`
- `content_flow`
- `keyword_hint`
- `tone_hint`
- `avoid_hint`

공통 통합 프롬프트와 업종별 세부 지침이 런타임에서 함께 결합되어야 한다.

### 3.5 통합 프롬프트 패키지

현재 운영 DB에는 업종군별 통합 프롬프트가 저장되어 있다.

대표 패키지:

- `local_professional_service`
- `food_service`
- `medical_health`
- `automotive_mobility`
- `pet_family_care`
- `local_professional_education`
- `sports_travel_leisure`
- `retail_fashion_lifestyle`

각 프롬프트는 다음 구조를 가진다.

- prompt key
- 이름
- 카테고리 그룹
- 버전
- 활성 상태
- 본문
- 생성일
- 수정일

새 고립 개발에서는 프롬프트 버전 이력과 롤백 기능을 반드시 추가한다.

### 3.6 사용량과 월간 한도

현재 무료 사용자의 월간 제작 한도와 실제 제작 사용량을 관리하는 구조가 있다.

기본 사업 방향:

- 무료 플랜 월 20회
- 유료 플랜 확장 사용량
- 관리자 수동 조정 가능
- 가입 후 일정 기간 체험 정책 가능
- AI 원고 생성과 MP4 제작을 별도 집계할 수 있도록 확장

사용량은 단순 숫자가 아니라 다음 세부 항목으로 분리되어야 한다.

- AI 원고 생성 횟수
- 브라우저 AI 생성 횟수
- API AI 생성 횟수
- 이미지 업로드 수
- MP3 생성 수
- MP4 생성 수
- 썸네일 저장 수
- 다운로드 수
- 보관함 저장 건수
- 저장 용량

### 3.7 Beta 보관함과 프로젝트 연결

운영 보관함은 사용자별로 격리되어야 한다.

각 프로젝트는 다음 자산을 가질 수 있다.

- SNS 8채널 결과
- 원본 이미지
- 워터마크 이미지
- MP3
- SRT
- MP4
- 대표 썸네일
- result.json
- 작업 설정

대표 썸네일은 자동 기본 선택 후 사용자가 재선택하면 마지막 선택이 최종 대표 이미지가 된다.

DB, result.json, 실제 PNG, 보관함 표시가 모두 일치해야 한다.

### 3.8 작업 큐

관리자는 전체 작업 흐름을 확인할 수 있어야 한다.

현재와 미래의 작업 상태 예시:

- created
- queued
- generating_prompt
- waiting_ai
- ai_processing
- content_ready
- tts_processing
- audio_ready
- rendering_video
- thumbnail_ready
- completed
- failed
- cancelled
- retrying

작업 큐 화면은 다음 기능이 필요하다.

- 실시간 상태
- 사용자
- 업체명
- 작업 ID
- 생성 방식
- AI Provider
- 진행률
- 시작 시간
- 경과 시간
- 오류 메시지
- 재시도
- 취소
- 강제 완료 처리
- 작업 상세 로그

## 6. 구독·과금 시스템

### 6.1 권장 플랜 구조

#### Free

- 월 20회
- 기본 SNS 8채널
- 기본 썸네일
- 광고 또는 StoryMaker 워터마크 정책 선택 가능
- 보관 기간 제한 가능

#### Basic

- 월 50회 또는 100회
- 광고 제거
- 보관 기간 확대
- 고급 썸네일
- 우선 작업 큐

#### Pro

- 월 300회 이상
- 다중 업체
- 고급 분석
- 팀원 초대
- 커스텀 템플릿
- API 사용량 포함

#### Business

- 다중 지점
- 관리자 계정
- 사용량 공유
- 화이트라벨
- 전담 지원
- 계약형 과금

## 16. 관리자 UI·UX 설계 원칙

- 현재 V1의 어두운 운영 콘솔 디자인을 계승한다.
- 카드와 표를 혼합한다.
- 중요한 상태는 배지로 표시한다.
- 위험 작업은 빨간색, 정상은 녹색, 주의는 노란색을 사용한다.
- 모바일에서도 조회는 가능해야 하지만 대규모 편집은 PC 중심으로 설계한다.
- 표는 열 선택, 정렬, 필터, 저장된 보기 기능을 지원한다.
- 회원 상세는 새 페이지 또는 큰 드로어로 연다.
- 관리자 화면의 모든 숫자는 클릭 시 상세 근거로 이동해야 한다.
- 빈 화면에는 다음 행동을 안내한다.
- 로딩·오류·권한 없음 상태를 명확히 구분한다.

## 25. Claude·Codex에게 전달할 실행 지시

당장 코드를 크게 수정하지 말고 먼저 현재 구조를 조사한다.

첫 산출물은 다음 다섯 가지다.

1. 인증·권한 경로 지도
2. 회원·구독·사용량 DB 스키마 지도
3. 관리자 화면 컴포넌트 지도
4. Beta 보관함·작업 큐 데이터 흐름 지도
5. 고립 개발용 단계별 구현 계획

조사 후 읽기 전용 관리자 대시보드를 가장 먼저 만든다.
