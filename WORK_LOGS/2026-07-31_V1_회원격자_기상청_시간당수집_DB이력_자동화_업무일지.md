## 신규 DB 테이블

### weather_active_grids

회원이 실제 사용하는 고유 격자와 회원·페르소나 수, 마지막 수집시간, 오류를 관리한다.

### weather_hourly_snapshots

시간별 실황 이력을 저장한다.

중복 방지 기준:

`UNIQUE(nx, ny, observed_hour)`

### weather_daily_grid_summaries

격자·날짜별 다음 값을 저장한다.

- 최저기온
- 최고기온
- 평균기온
- 대표 날씨
- 표본 수

기본키:

`PRIMARY KEY(nx, ny, weather_date)`

## 외부 API 호출 정책

- 호출 주기: 한 시간에 한 번
- 호출 단위: 활성 회원 수가 아니라 고유 `nx/ny`
- 로그인·페이지 조회·프롬프트 생성 시 외부 API 호출 금지
- V1 프롬프트의 `fetch_weather_and_temp()`는 최신 캐시, 직전 캐시 순서로 DB만 읽음
- 10분·20분 단위 날씨 timer 및 cron 없음
- 같은 시간 재실행 시 추가 호출 없음

## systemd 자동화

Timer 설정:

- `OnBootSec=2min`
- `OnCalendar=hourly`
- `Persistent=true`
- `AccuracySec=1min`
- `RandomizedDelaySec=20`

따라서 재부팅 후 2분 이내 활성화되며, 꺼져 있던 동안 놓친 실행도 `Persistent=true`로 복구한다.

## 주의사항

- `weather-server.service`의 기존 API 키나 설정을 새 코드에 복사하지 않았다.
- 기상청 격자 실황 수집기는 기존 Weather 프로젝트의 안전한 키 로더와 API 호출 함수를 재사용한다.
- Beta 날씨 생성 코드는 이번 작업 범위에서 수정하지 않았다.
- 저장소에 기존 미커밋 변경이 많으므로 이번 작업 파일 외 항목을 되돌리거나 일괄 커밋하지 않는다.
